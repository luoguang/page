Hexo 博客使用指南：从环境搭建到写作与发布

发表于 2026-10-16 分类于 教程
本站的完整工作流记录：新机器如何搭建环境、日常怎么写文章与放图片、本地预览与生成、如何发布到 GitHub Pages，以及 doc2md 转换小工具的用法。

这是一篇写给「未来的自己」的操作手册：换新机器时照着第二节装环境，日常写作照第三节，写完整站生成与发布看第四节，手上有一堆 Word / 文本笔记要搬上博客时看第五节。 🎯

一、整体流程

写 Markdown ──► hexo s 本地预览 ──► hexo g 生成静态站点 ──► hexo d 推送到 GitHub Pages
   ▲                                                              │
   └──────────────── 浏览器看到线上效果 ◄──────────────────────────┘

对应到本项目的命令：

环节 命令
搭建环境 npm install（外加确认 NexT 主题目录存在）
新建文章 hexo new "文章标题"
本地预览 npm run server（http://localhost:4000）
生成静态文件 npm run build
发布上线 npm run deploy
导入旧文档 npm run convert -- <文件或 zip>

二、环境搭建（新机器）

2.1 前置软件

软件 要求 说明
Node.js >= 20.19.0（推荐 22 LTS） Hexo 8 的硬性要求，低版本直接报错
npm 随 Node 安装 仅用于装依赖
Git 较新版本即可 拉取主题、部署时用

Windows 下装完校验一下：

node -v        # 期望 v20.19.0 或更高
npm -v
git --version

本项目还准备了离线包与一键脚本，脚本会自动检测：Node 已装且版本达标就跳过，缺了才用 deps/packages/ 里的离线包，随后安装 npm 依赖：

.\deps\install-deps.ps1          # Windows
bash deps/install-deps.sh        # Linux / macOS

2.2 取代码与装依赖

git clone <博客仓库地址> hexo
cd hexo
npm install

国内网络慢可以换镜像：

npm config set registry https://registry.npmmirror.com

若遇到 npm error Exit handler never called!，是旧格式 lockfile 触发的 npm 缺陷，删掉重建即可：

Remove-Item package-lock.json
npm install

2.3 确认主题存在

站点用 NexT 主题，位于 themes/next。该目录自带 .git，不会随站点仓库一起提交，换机器后经常是空的，需要单独克隆：

# 返回 False 就说明主题缺失
Test-Path themes\next\_config.yml

git clone --depth 1 -b v8.29.0 https://github.com/next-theme/hexo-theme-next.git themes\next

缺主题的表现是页面完全没有样式，或直接报 Script load failed: themes/next/scripts/...。

2.4 环境校验

npx hexo version    # 期望 hexo: 8.1.2
npx hexo clean
npx hexo g          # 期望 INFO  xx files generated
npx hexo s          # 打开 http://localhost:4000

能看到 NexT 风格的页面，环境就就绪了。hexo 命令本身来自 hexo-cli，可 npm install -g hexo-cli 全局安装；不装也能用 npx hexo 或项目里的 npm run 脚本。

三、写博客

3.1 新建文章

hexo new "文章标题"

会在 source/_posts/ 生成 文章标题.md，顶部 front-matter 按 scaffolds/post.md 的模板填好：

---
title: 文章标题
date: 2026-10-16 10:00:00
updated: 2026-10-16 10:00:00
categories:
  - 教程
tags:
  - Hexo
description: 一句话摘要，用于 SEO 与列表页。
keywords:
  - 关键词
---

几个约定：

  • 正文从 ## 开始，# 留给文章标题本身；
  • categories 是分类（一篇文章归一个类），tags 是标签（可多个）；
  • description 会进 <meta>，也会被列表页用到，值得认真写一句；
  • 想先写不发布，用草稿：hexo new draft "标题"，文件落在 source/_drafts/，预览时加 --draft。

3.2 首页摘要

在引言后插入 <!-- more -->：它之前的内容作为首页摘要显示，之后的内容在文章页展开。太长或没有 more 时，主题会自动截取开头，但可控性差，建议显式写。

3.3 图片与附件

站点开启了 post_asset_folder: true，新建文章时会同时生成同名资源目录：

source/_posts/
├── 文章标题.md
└── 文章标题/          # 这篇文章的图片放这里
    └── cover.png

在文章里这样引用：

{% asset_img cover.png 图片说明 %}

用资源目录的好处是图片跟着文章走，删文章时一起删，不会出现孤立文件。

3.4 排版规范

标题层级、列表、引用、代码块、表格、emoji 的写法，另有 这篇文章 专门记录，写新文章时照着套即可，所有文章的版式就能保持一致。

四、生成与发布

4.1 本地预览

npm run server      # 等价于 hexo server

默认 http://localhost:4000，改完 Markdown 刷新即可，不用重新生成。退出按 Ctrl+C。

4.2 生成静态站点

npm run clean       # hexo clean，清掉 public/ 与缓存
npm run build       # hexo generate，输出到 public/

public/ 就是最终要上线的目录，里面的路径都是相对路径（站点开了 relative_link），所以同一份产物放到域名根目录或子目录都能正常加载。

4.3 发布到 GitHub Pages

部署配置写在 _config.yml：

deploy:
  type: git
  repo: https://github.com/luoguang/page.git
  branch: master
  message: 'Site updated'

发布就一条命令：

npm run deploy

它做的三件事：hexo g 生成 → 把 public/ 推到上面那个仓库的 master 分支 → GitHub Pages 自动更新。该操作会强制覆盖远程分支，确认本地预览没问题再执行。

首次发布还需要两件一次性配置：

  1. 在 GitHub 上建仓库（这里是 luoguang/page），仓库可见性设为 Public；
  2. 仓库 Settings → Pages → Build and deployment，Source 选 Deploy from a branch，分支选 master、目录 / (root)，保存。

仓库名不是 <用户名>.github.io 时，线上地址会带子路径，例如 https://luoguang.github.io/page/，此时 _config.yml 里要同步：

url: https://luoguang.github.io/page
root: /page/

这两行错了会导致全站样式 404。发布后等一两分钟再访问，第一次构建比较慢。

4.4 发布后自检

首页               https://<用户名>.github.io/<仓库名>/
样式文件           .../css/main.css
某篇文章           .../2026/10/16/文章标题/
归档 / 分类 / 标签  .../archives/  .../categories/  .../tags/
订阅与搜索索引     .../atom.xml  .../search.xml

都能打开就说明发布成功。文章链接格式由 permalink 决定，本站是 :year/:month/:day/:title/。

五、小工具：doc2md 文档转换

手上有存量的 txt / doc / docx 笔记时，不用手工复制粘贴，用站点自带的转换工具直接生成 Markdown 与 front-matter。

5.1 安装

cd tools/doc2md
npm install

依赖全是纯 JS 包（mammoth、turndown、adm-zip、iconv-lite、js-yaml），不需要 Python，也不需要编译。.doc 转换依赖 LibreOffice 或 Word——只有要转 .doc 时才需要。

5.2 用法

在站点根目录用 npm 脚本调用（参数用 -- 透传）：

# 转换单个文件
npm run convert -- D:\docs\笔记.docx

# 带上标签与分类
npm run convert -- D:\docs\笔记.docx --tag 随笔,生活 --category 笔记

# 整个目录递归转换
npm run convert -- D:\docs

# zip 压缩包：自动解压后批量转换
npm run convert -- D:\docs\备份.zip

# 先预览不落地，确认标题和正文没问题再正式写入
npm run convert -- D:\docs\备份.zip --dry-run

# 覆盖同名文章
npm run convert -- 笔记.docx --force

常用参数：

参数 说明
-t, --title <标题> 指定标题，默认取文档首个一级标题或 TXT 首行
--tag <标签> / --category <分类> 多个用逗号分隔
--date <时间> YYYY-MM-DD HH:mm:ss，默认取文件修改时间
-o, --outdir <目录> 输出目录，默认 source/_posts
--force 覆盖已存在的同名文章
--dry-run 只预览不写文件

5.3 压缩包只支持 zip

工具只认 .zip：纯 JS 就能解，装完依赖即可用。.rar / .7z 是专有或 codec 复杂的格式，没有成熟的纯 JS 实现，要么引入几 MB 的 WebAssembly，要么调用本机解压软件——为了保持「零外部依赖」，这里不做。遇到 rar / 7z 先解压成目录，或重新打包成 zip 再导入。

已知限制：加密 zip、分卷 zip 不支持；zip 里的嵌套 zip 会自动展开（最多 2 层）；中文文件名会自动识别编码，不会乱码。

5.4 转换规则与后续步骤

  • 标题：docx 取首个一级标题，txt 取首行，再退化为文件名；
  • 日期：默认文件修改时间，可用 --date 改；
  • 图片：docx 内嵌图片导出到文章资源目录，正文用 {% asset_img %} 引用；
  • 编码：txt 自动识别 UTF-8 / UTF-16 / GBK，输出统一 UTF-8。

转换完照样走第四节：

npm run build
npm run deploy

六、常见坑速查

现象 原因 处理
页面没有样式 / 404 主题缺失或 url、root 与实际地址不符 克隆 NexT，核对 url 与 root
'hexo' 不是命令 未装命令行 npm install -g hexo-cli，或用 npx hexo
hexo -g 只打印帮助 参数写法错 生成是 hexo g，不是 hexo -g
npm error Exit handler never called! 旧格式 lockfile 删 package-lock.json 重装
中文或 emoji 乱码 文件存成了 GBK / ANSI 用编辑器另存为 UTF-8
部署后线上没变化 Pages 首次构建有延迟 等 1–2 分钟再刷新，确认仓库 Pages 已启用
导入的文档排版丢失 文本框、图表、批注等无法保留 转换后检查，复杂部分手工补

七、小结

  • 环境：Node 20.19+ → npm install → 确认 themes/next 存在；
  • 写作：hexo new → 填 front-matter → 图片放同名资源目录 → <!-- more --> 切摘要；
  • 发布：npm run server 预览 → npm run build → npm run deploy；
  • 存量文档：npm run convert，zip 直接导入，rar / 7z 先解压。

更详细的命令、主题配置与导入说明，见仓库里的 USAGE.md、SETUP.md、BUILD.md 与 tools/doc2md/README.md。
