Markdown 写作与排版规范

发表于 2026-10-14 分类于 教程
本站文章的推荐写法：从 front-matter 到标题层级、列表、引用、代码块、表格、图片与 emoji，一篇文把所有排版规则讲清楚。

本篇既是排版示范，也是本站的写作参考：从 front-matter 到标题层级、列表、引用、代码、表格、图片与 emoji，按这个模板写，任何一篇文章的版式都能保持一致。 🎯

一、front-matter

每篇文章顶部的 YAML 区块，决定了标题、归档、标签与 SEO 信息：

title: Markdown 写作与排版规范
date: 2026-10-14 10:30:00
updated: 2026-10-14 10:30:00
categories:
  - 教程
tags:
  - Markdown
description: 一句话摘要，用于 SEO 与列表页。
keywords:
  - Markdown
  - Hexo

字段说明：

字段 必填 作用
title 是 文章标题，同时决定 URL 与页面 <h1>
date 是 发布时间，决定归档目录；缺失会被生成到错误日期目录
updated 否 最后更新时间，NexT 显示在标题下方
categories 否 分类，有层级，一篇文章建议只用一个
tags 否 标签，平级，可多个
description 否 摘要，用于 SEO 描述
keywords 否 关键词列表

categories 与 tags 的区别：分类是树（如「教程 > Hexo」），标签是云。分类用列表缩进表示层级。

二、标题层级

正文统一从 ## 开始，# 留给文章标题本身（它由 title 自动生成）。层级建议不超过四级：

  • ## 一级章节
  • ### 章节下的小节
  • #### 再下一层，通常够用

2.1 小节示例

标题里不要嵌套 Markdown 语法，末尾也不加标点——目录（toc）会原样收录标题文字。

三、正文排版

段落与强调

段落之间空一行。加粗表示重点，斜体表示次要强调，行内代码用于命令、文件名与配置键。

中英文之间留一个空格：本站使用 Hexo 8 与 NexT 主题，站点配置写在 _config.yml，主题配置写在 _config.next.yml。

列表

无序列表用 -：

  • 项目一
  • 项目二
    • 嵌套项缩进两个空格

有序列表用数字，适合写步骤：

  1. 先执行 npm run clean
  2. 再执行 npm run build
  3. 最后上传 public/ 目录

任务列表用于记录进度：

  • 完成环境搭建
  • 绑定自定义域名

引用

引用块用来放结论、注意事项或引用他人内容。
连续多行时，每行前都要加 >。

分割线

两个章节之间需要明显分隔时，单独一行写 ---。

四、代码块

代码块必须标注语言，否则不会高亮。行号由 prismjs.line_number 全局开启，无需额外配置：

npm run server          # 本地预览
npm run build           # 生成静态文件
relative_link: true     # _config.yml：生成相对路径
cache:                  # _config.next.yml：与 relative_link 互斥
  enable: false
const fs = require('fs');
fs.writeFileSync('out.txt', 'Hello Hexo', 'utf8');

需要在文中展示「代码块本身」时，用四个反引号包裹三个反引号：

```yaml
theme: next
```

五、表格

表格适合放参数、对照与清单，对齐用第二行的冒号控制：

元素 语法 用途
链接 [文字](https://example.com) 站内用相对路径，站外用绝对 URL
图片 ![说明](路径) 见下一节
任务 - [x] 记录完成状态

六、图片与附件

站点开启了 post_asset_folder: true，每篇文章可以有同名资源目录，图片放进去后用相对路径引用：

![示意图](cover.png)

公共图片放在 source/images/，用站点路径引用：

![站点 Logo](/images/logo.svg)

建议：截图类图片 alt 文字写清「这是什么」，便于搜索与无障碍阅读；大图先压缩再上传。

七、Emoji

直接输入字符与短代码等价，两种都可以用：

写法 效果
🎉 🎉
<span class="github-emoji" alias="tada" style="height: 1.2em; width: 1.2em; vertical-align: middle" fallback-src="https://github.githubassets.com/images/icons/emoji/unicode/1f389.png?v8">&#x1f389;</span> 🎉
{% emoji sparkles %} ✨

自定义表情包：把图片放到 source/images/emoji/，在 _config.yml 的 emoji.customEmojis 中登记，之后就能用 :doge: 引用。

标题里不建议放 emoji，正文中点缀即可。

八、常见错误

错误写法 问题 正确做法
正文用 # 标题 与文章标题重复，目录层级混乱 正文从 ## 开始
代码块不标语言 不会高亮，阅读吃力 标注 bash、yaml、js 等
front-matter 缺 date 文章被生成到错误日期目录 补上 date
中英文不加空格 排版拥挤 中英文之间留一个空格
用记事本保存 md 默认 ANSI 编码，中文与 emoji 乱码 用 VS Code 等编辑器保存为 UTF-8

九、小结

  • front-matter 写全，尤其别漏 date
  • 正文从 ## 起，层级不超过四级
  • 代码块标注语言，表格用标准语法
  • 中文与英文之间留空格，文件统一 UTF-8

照这个模板写，文章在 NexT 的 Pisces 布局下会自动获得目录、代码高亮、行号与一致的行距。 🎉
